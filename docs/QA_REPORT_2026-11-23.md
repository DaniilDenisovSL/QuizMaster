# Quiz Master — тестування та виправлення

Дата: 23.11.2026. Проєкт: LR2_QuizMaster, надана користувачем версія 5.

## Результат

Перевірено код і виконано тести на Windows із .NET SDK 10.0.401, WinForms, 96 DPI. Виправлено 10 груп дефектів, відтворених доданими регресійними тестами. Із 20 нових сценаріїв до виправлень проходили 10, після виправлень — усі 20. Базові 11 перевірок також проходять.

Виправлення зроблено в окремій копії: вихідну папку `D:\team work\labs\LR2_QuizMaster` не змінено, оскільки середовище має до неї лише доступ для читання. Особисту таблицю рекордів не використовували: перевірки записували дані в окремі тестові файли.

|---|---|---|

| Початкові перевірки backend | 11/11 | `qa-logs/backend-final.log` |

Кількості в різних рядках не підсумовуються: набори мають перетини, а перевірки геометрії та сценарії гри мають різну деталізацію.

Перевірка рекордів також контролює `CorrectAnswers <= QuestionsPlayed <= TotalQuestions`, `0 <= BestStreak <= CorrectAnswers`, скінченну Accuracy у [0;1] та її відповідність відношенню правильних відповідей до зіграних питань. Старі некоректні записи можуть більше не відображатися; попередження та резервна копія під час наступного збереження дозволяють зберегти вихідні дані для аналізу.

## Непідтверджені перевірки та межі

Звичайний запуск GameChecks до і після виправлень зупинився на `System.Exception: F11 consumed`. Цей запуск не вважається успішним. Причину відмови активного вікна в цьому середовищі остаточно не встановлено; потрібна перевірка F11/Esc у видимому активному застосунку. У режимі `--no-focus` ці перевірки позначаються SKIP, а не PASS. Перехід у fullscreen через WindowPresentation.ToggleFullScreen перевірено окремо і він працює.

Не перевірялися вручну native діалоги підтвердження: у UI-тестах підставлялися Yes/No, а логіка паузи й продовження виконувалася реально. Не перевірялися 150%/200% DPI, кілька моніторів, інший Windows-ПК, інсталяція, довготривала робота чи зовнішні процеси, які одночасно записують один файл. Поточні тести конкурентності стосуються кількох екземплярів у межах одного процесу. Фактичну правильність усіх енциклопедичних відповідей у банку не звіряли із зовнішніми джерелами; перевірено структуру й зв’язки даних.

Отже, підтверджено виправлення перелічених дефектів і проходження зазначених наборів. Повне приймальне тестування клавіатури й різних конфігурацій екрана ще не завершене.

## Як повторити

Відкрити `.slnx` у Visual Studio або виконати в папці розпакованого проєкту:

```powershell
dotnet build .\LR2_QuizMaster.slnx -m:1
dotnet run --project .\LR2_QuizMaster.Tests\LR2_QuizMaster.Tests.csproj
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --data-audit
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --no-focus
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --menu
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --layout --no-focus
```

UI-набори потрібно запускати послідовно. Для повної клавіатурної перевірки у звичайному активному сеансі Windows повторити ігровий і layout-набори без `--no-focus`; результат F11/Esc перевірити також вручну. Прапорець `--dpi-aware` використовує поточний DPI Windows і сам не встановлює масштаб екрана.
