# Підключення інтерфейсу до backend

Форми використовують `QuestionBank`, `QuizSession`, `QuizCatalog` та `LeaderboardStore`. Бізнес-логіку backend не переписано. Старий `UI_INTEGRATION.patch` застосовувати не потрібно.

## Оновлення 30.10.2026

- Усі 150 питань отримали відповідні за змістом варіанти: роки до років, імена до імен, числа з відповідними одиницями. Правильні відповіді та ID збережені; уточнено три неоднозначні формулювання. Причиною невідповідностей був сам JSON-банк, а не алгоритм перемішування.
- `GameSetupForm` більше не містить прапорців перемішування та пов'язаних властивостей. `MainMenuForm` передає фіксований порядок питань і відповідей (`ShuffleQuestions = false`, `ShuffleAnswers = false`). Можливості backend залишені сумісними для інших клієнтів.
- Три кнопки складності мають виділення вибраного рівня, плавний hover, короткі описи та підказки. Категорії також отримали підказки.
- Кнопка виходу, Esc у віконному режимі та закриття вікна запитують підтвердження незавершеного тесту. Типовий вибір — залишитися. `PausableQuizClock` призупиняє час на період підтвердження; після відмови питання, бали, життя й залишок часу зберігаються. Підтверджений вихід перериває сесію без запису незавершеного результату.
- Вичерпання життів показує «Цього разу програно», рожеву іконку поразки та кнопку повторної спроби. Звичайне завершення має зелену галочку.
- `WindowNavigation` зберігає попереднє вікно під новим до завершення появи, потім робить його невидимим. Зворотний перехід плавно прибирає поточне вікно. Дочірні діалоги не створюють додаткових кнопок на панелі задач.
- F11 та Esc обробляє лише активне дозволене вікно. Зміни рамки захищені від повторного входу через події видимості та активації. Esc виходить з повного екрана того самого екземпляра, відновлює звичайний або максимізований режим і не закриває тест.

## Перевірки

11 backend-перевірок включають усі 15 комбінацій категорії/складності з фіксованим і випадковим порядком, відповідність кожного набору відповідей своєму питанню та чотири числові роки у питаннях про роки.

Окремі UI-перевірки охопили шість сценаріїв: кнопки складності й відсутність прапорців; п'ять циклів F11/Esc і повернення максимізації; підтвердження кнопки виходу та закриття, паузу й відновлення часу; вкладений повноекранний діалог і повернення без видимого дубля; завершення та поразку з одноразовим збереженням; повний шлях головне меню → налаштування → тест → підтверджений вихід → меню.

Тести використовували окремі сховища. Рекорди користувача в `LocalApplicationData/QuizMaster/leaderboard.json` не змінювалися.
