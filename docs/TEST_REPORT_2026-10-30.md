# Quiz Master — звіт про перевірку та доопрацювання

Дата: 30.10.2026. Середовище: Windows, .NET 10, WinForms; 96 DPI та 144 DPI (масштаб 100% і 150%).

## Що зроблено

У фулстек-частині створені п'ять форм, темний дизайн, іконки, hover-ефекти, кнопки складності з описами, переходи та відображення даних наявного backend. Додано підтвердження виходу з паузою часу, фактичні результати, окремий стан поразки та збережені рекорди. Прапорці перемішування видалено; інтерфейс використовує фіксований порядок. Раніше виправлено невідповідні варіанти у 150 питаннях; правильні відповіді та ID збережені.

У цьому доопрацюванні:

- Вікно рекордів має фіксований розмір, центрується та враховує доступну область екрана. Рамку, максимізацію та F11 заблоковано тільки для цього вікна. Інші форми зберігають свої режими.
- Заблоковано ручне розтягування шапки, рядків і колонок таблиці. Ширини колонок автоматично розподіляються між доступним місцем.
- Виправлено окреме DPI-масштабування висоти шапки та рядків: при 96 DPI — 46/49 px, при 144 DPI — 69/73 px.
- Повідомлення порожнього списку розміщено всередині тіла таблиці, під шапкою, по центру. Воно не перекриває назви колонок і не створює смугу іншого кольору.
- Додано проєкт `LR2_QuizMaster.UiTests` із повторюваними перевірками форм, таблиці та окремим аудитом некоректних вхідних даних.

## Що перевірено

Перевірки форм виконані програмно на справжніх WinForms-формах із реальними `QuestionBank`, `QuizSession` та `LeaderboardStore`; додатково переглянуто знімки інтерфейсу. Це не тотожне ручному кліканню всіх сценаріїв на різних ПК.

| Група | Обсяг | Результат |
|---|---|---|
| Backend-перевірки | 11 перевірок, включно з усіма категоріями/складностями та збереженням | Пройдено |
| Ігровий UI, 100% | 22 сценарії | Пройдено |
| Ігровий UI, 150% | Ті самі 22 сценарії | Пройдено |
| Таблиця, 100% | 53 перевірки розмірів, режимів, записів і фільтрів | Пройдено |
| Таблиця, 150% | Ті самі 53 перевірки | Пройдено |
| Аудит некоректних даних | 4 негативні випадки | Виявлено 2 відкриті проблеми, описані нижче |

Ігрові сценарії: вибір рівня та описи; повторні F11/Esc і повернення максимізації; скасування/підтвердження виходу через кнопку та закриття; пауза й відновлення часу; усі 10 питань кожної з 15 комбінацій категорії та складності; прив'язка тексту до ID відповіді; захист від повторного натискання; таймаут, продовження, скидання поточної та збереження найкращої серії; повне завершення; поразка; одноразове збереження; помилка запису без втрати підсумку; шлях меню → налаштування → тест → підтверджений вихід → меню.

Сценарії таблиці: 12 записів зі скролом, порожній файл, порожня категорія, повернення до заповненої категорії, незмінність розміру при спробах збільшити/зменшити, блокування шапки/колонок, відсутність підказки недоступного F11, відкриття з повноекранної форми та повернення до неї.

Усі перевірки використовують окремі тестові сховища. Файл рекордів користувача не очищався й не редагувався.

## Знайдені та виправлені недоліки інтерфейсу

| ID | Причина | Виправлення |
|---|---|---|
| UI-RESIZE-01 | DataGridView дозволяв вручну збільшувати висоту шапки та ширину колонок | Вимкнені відповідні режими зміни розміру |
| UI-DPI-02 | Висоти шапки й шаблону рядка помилково ділилися на DPI під час збереження початкових розмірів | Для цих метрик використане одноразове масштабування з дизайнерських 96 DPI |

## Що треба допрацювати бекендеру

### DATA-01 — пропущені категорія та складність непомітно замінюються типовими значеннями

Пріоритет: середній. Місце: `Backend/Services/QuestionBank.cs`, DTO та десеріалізація.

Відтворення: взяти коректне питання `programming-medium-001`, видалити поле `category` з JSON та завантажити банк. Замість помилки отримуємо `Games/Medium`. Якщо видалити `difficulty`, отримуємо `Programming/Easy`.

Причина: поля enum у DTO не nullable, тому відсутність поля перетворюється на значення enum `0`, яке проходить перевірку `Enum.IsDefined`.

Очікування: відсутність обов'язкової категорії або складності має відхиляти банк зі зрозумілим повідомленням. Варіанти виправлення: required-поля або nullable DTO з явною перевіркою наявності. Додати регресійні перевірки обох випадків.

### DATA-02 — недостатня валідація записів таблиці рекордів

Пріоритет: середній. Місце: `Backend/Services/LeaderboardStore.cs`, `LoadUnsafeAsync` / `IsValidRecord`.

Відтворення 1: завантажити окремий файл рекордів із вмістом `[null]`. Виникає `NullReferenceException` під час фільтрації.

Відтворення 2: завантажити інакше коректний запис з числовою категорією `99`. Запис проходить завантаження, а перетворення категорії на назву для інтерфейсу викликає `ArgumentOutOfRangeException`.

Очікування: пропускати або відхиляти некоректні записи з попередженням; не передавати їх формі. Перевіряти null, допустимі enum, а також узгоджені межі числових полів (`CorrectAnswers <= QuestionsPlayed <= TotalQuestions`, невід'ємні бали, точність у межах 0–1).

Основну backend-логіку в цій роботі не змінено. Ці дві проблеми залишені відкритими для відповідального за backend і відтворюються командою аудиту.

## Подальші доробки та межі перевірки

1. Спочатку закрити DATA-01 та DATA-02 й домогтися успішного проходження аудиту даних.
2. Команді окремо перевірити зміст і однозначність фактів у питаннях. Автотести перевіряють структуру, зв'язки відповідей і роки, але не підтверджують історичну або предметну достовірність кожного факту.
3. Перевірити перенесення між моніторами з різним DPI, масштаб 200% і менші робочі області. У цій перевірці підтверджено 100%/150%; фізичне переміщення між різними моніторами не перевірялося.
4. Перед передачею роботи перевірити опубліковану збірку на іншому Windows-ПК. Відтворювані перевірки в поточному середовищі цього не замінюють.
5. Як додаткову функцію можна додати розбір помилок після гри. Зараз результат показує загальну статистику.

## Як повторити

Із папки рішення:

```powershell
dotnet build .\LR2_QuizMaster.slnx
dotnet run --project .\LR2_QuizMaster.Tests\LR2_QuizMaster.Tests.csproj
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --dpi-aware
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --layout
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --layout --dpi-aware
dotnet run --project .\LR2_QuizMaster.UiTests\LR2_QuizMaster.UiTests.csproj -- --data-audit
```

Прапорець `--dpi-aware` використовує поточний DPI Windows; у перевіреному середовищі це 144 DPI. Артефакти за замовчуванням потрапляють у `%TEMP%/QuizMasterUiTests/<дата-час>`. Не запускайте UI-набори одночасно: вони перевіряють активне вікно.

Аудит `--data-audit` наразі завершується кодом 1: відтворює чотири випадки двох відкритих дефектів. Це окремо від успішних основних сценаріїв, а не підтвердження готовності всіх перевірок.
